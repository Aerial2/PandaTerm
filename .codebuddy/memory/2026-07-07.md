# 2026-07-07

## 修复：连接管理列表行拖拽不动（Tauri 下 HTML5 draggable 显示禁止光标）
- 现象：连接管理窗口（ConnectionWindow.tsx）里保存连接的表格行无法拖拽重排，鼠标显示"禁止"光标。
- 根因：原实现用 HTML5 原生 `draggable` + `onDragStart/onDragOver/onDrop`。在 Tauri 的 webview 中，这种页面内原生拖拽会触发 forbidden-cursor 且拖不动（和文件拖放进窗口的 forbidden-cursor 是同一类 Tauri/webview 行为问题）。
- 修复（参考 App.tsx 终端 tab 拖拽写法）：
  - 移除 `<tr>` 上的 `draggable` 和所有 HTML5 drag handler，改为 `onPointerDown -> startConnectionRowDrag`。
  - 新增 `startConnectionRowDrag`：pointerdown 记录起点，`window` 监听 `pointermove`/`pointerup`；位移超过 `CONNECTION_DRAG_THRESHOLD=12` 才激活拖拽（不影响普通点击/双击），通过 `document.elementFromPoint` 命中悬停行作为放置目标，pointerup 调用已有的 `handleReorderSessions` 重排并持久化。
  - 用 `connectionDidDragRef` 在拖拽后抑制接踵的 `onClick`，避免误选中目标行；双击连接、右键菜单保持不变。
  - 搜索过滤（connectionSearchQuery 非空）时禁用排序。
  - CSS：`.connection-row` 加 `user-select:none; -webkit-user-drag:none; touch-action:none;`；新增 `.connection-row.drop-target` 顶部高亮指示线、`.connection-row.dragging` 半透明、`body.connection-reordering` 拖拽中禁选区。
- 已在 ConnectionWindow.tsx 的 ref 声明处加注释标记此坑，提醒勿改回 HTML5 draggable。
- 验证：`tsc --noEmit` 通过，前端 lint 0。
- 二次修复（同文件，拖拽不生效的第二坑）：`onUp` 闭包里读 `dragOverId` state 拿到的是拖拽开始那次渲染的旧值（恒为 null），导致 `handleReorderSessions` 从未被调用、顺序不变。把放置目标 id 同时存进 `connectionDragRef.current.targetId`（onMove 写 / onUp 读 ref），不再依赖过期闭包变量。经验教训：pointer 拖拽里"当前悬停目标"这类随移动变化的值，必须放 ref，不能放 state 后在 onUp 闭包里读。

## 功能：连接管理表格表头列宽可拖拽调整
- 需求：用户先要"名称"列更宽（27%→36%），再要求"表头支持拖动"= 表头列宽可拖拽 resize。
- 实现（ConnectionWindow.tsx + styles.css，参考 App.tsx 终端面板分割线 resize 的 pointer 写法）：
  - CSS：`.connection-table` 加 `table-layout: fixed;`（百分比列宽严格生效）；`.connection-table th` 加 `position: relative;`；新增 `.conn-col-resizer`（绝对定位于表头右缘 right:-3px、cursor:col-resize、touch-action:none，hover/active 显示竖线）。
  - state：`connColumnWidths`（index/name/host/user/protocol/port 百分比，合计 100）、`connTableRef`、`connColDragRef`。
  - `startConnColResize(col, event)`：`setPointerCapture` + window 监听 pointermove/up；按表格像素宽度换算 delta 百分比，调整"该列 + 右邻列"宽度（总和不变），做 MIN=4% 夹紧；末列（端口）不加手柄。
  - `<table>` 加 ref，每个 th 用 style width 驱动并内嵌 resizer span（末列无）。
- 验证：`tsc --noEmit` 通过、前端 lint 0。
- 追加（列宽持久化）：拖动后需持久化，否则重开窗口又得重拖。列宽属纯 UI 偏好，用 localStorage 存（key=`pandaterm.connColumnWidths`），不动后端。
  - 初始 state 改为 `loadConnColumnWidths()`（读 localStorage，损坏/缺失则回落 `CONN_COLUMN_DEFAULT_WIDTHS`，仅保留 >0 的合法值）。
  - 新增 `connColumnWidthsRef` 持有最新宽度；`onMove` 函数式更新内同步 `connColumnWidthsRef.current = next`；`onUp` 松手时一次性 `localStorage.setItem(...)` 写入（避免拖动中每帧写、且规避闭包过期）。隐私模式 setItem 失败 try/catch 忽略。

## 项目约定 / 踩坑提醒（重要，跨会话）
- Tauri 应用里**不要使用 HTML5 原生 drag-and-drop**（包括 `draggable` 元素拖拽、从 OS 拖文件进窗口）：一律显示禁止光标且行为异常。
  - 页面内元素拖拽（终端 tab/面板、连接列表行）：改用 **pointer events 自行实现**（pointerdown/move/up + setPointerCapture）。终端实现见 App.tsx `startTabPointerDrag`/`startPaneTabPointerDrag`。
  - 从系统拖文件进窗口上传：已在 `tauri.conf.json` 设 `dragDropEnabled: false`，并靠顶层 `onDragOver` preventDefault（App.tsx `handleGlobalDragOver`）消除 forbidden-cursor。
- 大文件（>~2MB）上传卡死是 SSH 双向流控死锁（见 2026-07-06 记录），已修：上传期间须并发排空通道输出。
- 二次修复（上传死锁的遗漏点，本次卡死根因）：用户拖放文件 `fsl-chat-linux`(47MB) 上传卡在 2.0MB/47MB。之前只在 `stream_upload_file`（有本地路径的流式上传 `upload_local_file`）加了 channel.split + 后台排空 server→client 输出窗口的修复；但 `write_remote_file_content`（用于前端 base64 降级路径 `uploadFile`/`upload_file`——即拖放无本地路径的文件、以及编辑器保存 `write_remote_file`）**漏了**此修复，仍是单 channel `data()` 循环 + 末尾 `wait()`。OpenSSH 在 ~2MB 初始窗口处因输出窗口未被消费而停止通告输入 WINDOW_ADJUST，导致 `data()` 永久挂起。修复：把 `write_remote_file_content` 也改成 `channel.split()` + `tokio::spawn` reader 持续排空输出（与 `stream_upload_file` 完全一致），并把 `let mut channel` 改为 `let channel`。`cargo check` 通过无 warning。教训：**任何走 `cat > path` 的 SSH 写入通道都必须 split + 并发排空输出窗口**，否则大文件一律死锁在 ~2MB；新增写入通道时务必沿用此模式，勿再漏。
- 注：前端 `uploadFiles` 仅在 `!local && terminalId && localPath` 时走流式 `uploadLocalFile`；拖放（Drop）进来的文件通常没有本地 `localPath`，会走 `uploadFile` base64 降级路径 → `write_remote_file_content`，所以此路径也必须健壮。
