## 修复：分屏后打开远程文件，编辑器"左边空白、右边才有内容"
- 现象：分屏（split）后打开远程服务器文件，左侧 pane 编辑器空白，右侧 pane 才显示文件内容。
- 根因：分屏下会挂载**两个** `EditorPanel` 实例（App.tsx `showWorkspaceChips` 的两个条件分别命中：workspace 所在 pane + 当前活动 pane），二者共享同一份 `editorTabs` / `activeEditorTabId`。model URI 仅由 tabId 生成 → 两实例算出同一 URI；后挂载者在 `ensureModel` 里把先挂载者已绑定并显示的 model 当成 stale `dispose()` 后重建 → 先渲染的（左）model 被销毁变空白，后渲染的（右）正常。渲染顺序决定了"先左空白、后右有内容"。
- 修复：`apps/desktop-ui/src/EditorPanel.tsx` 的 `ensureModel` 改为复用全局已存在 model（`monaco.editor.getModel(uri)` 命中未 dispose 即直接复用并记入本实例 `modelsRef`），不再 dispose。多实例共享同一 model，内容同步。
- 编辑器技术栈：Monaco（`@monaco-editor/react`），实现在 `apps/desktop-ui/src/EditorPanel.tsx`；App.tsx 有两处渲染（pane 内嵌 ~6340 行 / 无终端时占满主区 ~7725 行，二者互斥）。

## 远程保存"Ctrl+S 延迟 + 有时不成功"
- 保存链路：`saveEditorFile`(App.tsx ~2210) → invoke `write_remote_file`(main.rs ~2352) → `connect_russh_transfer_session` → `write_remote_file_atomic` = ①开 channel exec `cat > xx.part` 分块写 ②**再开一个 channel** exec `mv -f` 提交。
- 延迟根因：一次保存 = **2 次 SSH 通道建立 + exec 往返**；若传输连接失效会 invalidate 后用 interactive handle **再重试一轮**（又 2 次往返）。
- "有时不成功"根因（已修）：`write_remote_file_content` / `stream_upload_file` 的 read_task 只保留 stdout **前 128 字节**，而完成标记 `__PANDATERM_UPLOAD_COMPLETE__`(29B) 是 `cat` 成功后**最后**才打印的。远端若先输出 banner/motd/警告 >~99B，标记即被截断 → `completion_marker_seen=false` → 报"未收到完成标记"，**明明写成功却判失败**。
- 修复：新增 `REMOTE_OUTPUT_TAIL_LIMIT = 4096`，两处改为**保留尾部**（标记在末尾必命中）；stderr 同改（原 512B 会截断真实原因如 Permission denied）。
- 顺带：App.tsx `saveEditorFile` 保存前先 `setStatusMessage` 提示"正在保存"，避免等到完成才有反馈、加剧"感觉延迟"。
- 待办（待用户确认）：把"写临时 + mv 提交"合并为**一次 exec**（`if cat > tmp && mv -f tmp dest; then printf marker; fi`），保存从 2 次 SSH 往返降为 1 次，延迟约减半且仍原子。但 `write_remote_file_content` 被上传等多处复用，改动面较大，未擅自改。
