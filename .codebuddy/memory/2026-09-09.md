## 修复：分屏后打开远程文件，编辑器"左边空白、右边才有内容"
- 现象：分屏（split）后打开远程服务器文件，左侧 pane 编辑器空白，右侧 pane 才显示文件内容。
- 根因：分屏下会挂载**两个** `EditorPanel` 实例（App.tsx `showWorkspaceChips` 的两个条件分别命中：workspace 所在 pane + 当前活动 pane），二者共享同一份 `editorTabs` / `activeEditorTabId`。model URI 仅由 tabId 生成 → 两实例算出同一 URI；后挂载者在 `ensureModel` 里把先挂载者已绑定并显示的 model 当成 stale `dispose()` 后重建 → 先渲染的（左）model 被销毁变空白，后渲染的（右）正常。渲染顺序决定了"先左空白、后右有内容"。
- 修复：`apps/desktop-ui/src/EditorPanel.tsx` 的 `ensureModel` 改为复用全局已存在 model（`monaco.editor.getModel(uri)` 命中未 dispose 即直接复用并记入本实例 `modelsRef`），不再 dispose。多实例共享同一 model，内容同步。
- 编辑器技术栈：Monaco（`@monaco-editor/react`），实现在 `apps/desktop-ui/src/EditorPanel.tsx`；App.tsx 有两处渲染（pane 内嵌 ~6340 行 / 无终端时占满主区 ~7725 行，二者互斥）。

## 远程保存"Ctrl+S 延迟 + 有时不成功"
- 保存链路：`saveEditorFile`(App.tsx ~2210) → invoke `write_remote_file`(main.rs ~2352) → `connect_russh_transfer_session` → `write_remote_file_atomic` = ①开 channel exec `cat > xx.part` 分块写 ②**再开一个 channel** exec `mv -f` 提交。
- 延迟根因：一次保存 = **2 次 SSH 通道建立 + exec 往返**；若传输连接失效会 invalidate 后用 interactive handle **再重试一轮**（又 2 次往返）。
- "有时不成功"根因（已修）：`write_remote_file_content` / `stream_upload_file` 的 read_task 只保留 stdout **前 128 字节**，而完成标记 `__PANDATERM_UPLOAD_COMPLETE__`(29B) 是 `cat` 成功后**最后**才打印的。远端若先输出 banner/motd/警告 >~99B，标记即被截断 → `completion_marker_seen=false` → 报"未收到完成标记"，**明明写成功却判失败**。
- 修复：新增 `REMOTE_OUTPUT_TAIL_LIMIT = 4096`，两处改为**保留尾部**（标记在末尾必命中）；stderr 同改（原 512B 会截断真实原因如 Permission denied）。
- 顺带：App.tsx `saveEditorFile` 保存前先 `setStatusMessage` 提示"正在保存"，避免等到完成才有反馈、加剧"感觉延迟"。
- 待办（待用户确认）：把"写临时 + mv 提交"合并为**一次 exec**（`if cat > tmp && mv -f tmp dest; then printf marker; fi`），保存从 2 次 SSH 往返降为 1 次，延迟约减半且仍原子。但 `write_remote_file_content` 被上传等多处复用，改动面较大，未擅自改。

## 编辑器宿主 pane（editorHostPaneId）
- 用户反馈：左边 pane 打开文件后点右边 pane，左边的编辑器消失、变回终端第一个标签。
- 根因：`activePaneId` 跟随焦点变化（focusTerminalPane 更新 `tab.activePaneId`，且它会 `setShowEditor(false)`），把编辑器渲染条件绑在它上面 = 焦点一动编辑器就搬家。
- 修复：新增 `editorHostPaneId` state（编辑器宿主 pane）：
  - `openFileInEditor`（existing 与新建两处）和 `selectEditorWorkspaceTab` 都记录 `setEditorHostPaneId(activePaneIdRef.current)`。
  - pane 内 editor host 渲染条件与 `showWorkspaceChips` 的 editor 部分统一改为 `(editorHostPaneId ?? activePaneId) === node.tabId`（文件标签栏跟随编辑器所在 pane）。
  - 兜底 effect：宿主 pane 从当前 workspace 布局移除时（关闭分屏/切换连接）重置为 null，回退到 activePaneId。用 `collectTerminalLayoutTabIds` 检查。
  - `focusTerminalPane` 里的 `setShowEditor(false)` 保留：pane 的 onMouseDown 在 showEditor 时直接 return 不会触发它，它只在点 workspace/终端标签（主动切走）时生效，属原设计。
- 交互语义：编辑器固定在打开它的 pane；想在另一侧显示，在另一侧点文件标签即可。
- 后续反馈：文件标签在分屏的每个 pane 标签栏都重复出现（`renderEditorTabItems()` 无条件渲染全局 editorTabs）。修复：`renderUnifiedPaneTabbar` 中文件标签仅在下述情况渲染——`!paneTabId`（无终端时的主区独立标签栏）或当前 pane 是编辑器宿主（`(editorHostPaneId ?? activePaneId) === paneTabId`）。
- 又一反馈：编辑器宿主 pane 的标签栏把**全部服务器连接标签**（`renderWorkspaceTabItems()` 渲染的全局 workspace tabs）也带出来了，用户误以为新建了连接 tab。修复：`renderPaneLeaf` 调用 `renderUnifiedPaneTabbar` 的第 3 参数从 `showWorkspaceChips` 改为 `isWorkspacePane`——连接标签只挂 workspace 根 pane；宿主 pane 的标签栏只有文件标签 + 自己的终端 tab。主区独立标签栏（`paneTabId=undefined`、传 `true`）不受影响。
- 回归修正：上一步把第 3 参数改为 `isWorkspacePane` 后，文件标签条件仍挂在 `showWorkspaceTabs` 上 → 宿主 pane（非根 pane）的文件标签被短路、打开文件不显示标签。已解耦：文件标签独立判断 `(!paneTabId || host匹配)`，不再依赖 showWorkspaceTabs。**教训：改函数参数语义时必须排查该参数的所有消费点。**
- 再修：点击服务器（workspace）tab → `focusTerminalPane` → `setShowEditor(false)`（切回终端视图），而文件标签条件含 `showEditor &&` → 整组文件标签随之隐藏。已去掉该依赖：文件标签只要 pane 是宿主就**常驻**显示；编辑器视图关闭时仅收起编辑器区域，点文件标签（`selectEditorWorkspaceTab` 会重新 `setShowEditor(true)`）随时回去。

- 重构：**废弃全局 `editorHostPaneId`，改为每个 `EditorTab.hostPaneId`**（打开时记录 `activePaneIdRef.current`）：

- `archive.rs`：zip 的 python3 fallback `extractall` 有 Zip Slip 风险（`../`/绝对路径成员可写出解压目录）。改为解压前校验每个成员：`posixpath.normpath(n).startswith('..')` 或 `isabs` 则 `sys.exit`。
- `rdp.rs TileBatch::push`：脏矩形由远端驱动可能超出 DecodedImage 边界 → 越界切片 panic；改为逐行校验 `src_row_start + row_bytes > src.len()` 则 break。

## 第四轮（用户"都按建议的来"，全部已修，tsc + cargo check 5.40s 通过）
- **`RdpView.tsx` RDP 剪贴板（安全）**：删除 500ms 后台轮询上行与连接后的立即上行，改为 `sendLocalClipboard(force)` **仅在用户主动 Ctrl/Cmd+V 或 Shift+Insert 时**上行（force 允许重复粘贴同一内容）；远端→本地的自动写入保留（RDP 预期行为）。避免本地复制的密码/令牌被无感知推送给远程主机。
- `RdpView.tsx`：error 态补「重新连接」按钮（原先只有 disconnected 态有，网络抖动后无法恢复）。
- `LocalTerminalView.tsx`：Ctrl+V 改为复用 `prepareTerminalPaste`（超长截断 + `requiresConfirmation` 时 `window.confirm`），与远端 SSH 粘贴行为一致，防止含 ESC 等控制序列的剪贴板直接注入本地 shell。
- **`mcp.rs`**：
  - `McpRuntime` 新增 `call_locks: Mutex<HashMap<String, Arc<Semaphore(1)>>>`，`call_tool` 先 acquire 再 take live → 同一 server 串行，修复并发调用互相挤兑误判"会话未连接"；`disconnect_server`/`disconnect_all` 同步清理 call_locks。
  - `spawn_stdio_session` 结束前校验 slot 仍为 `connecting`，否则杀子进程并返回错误 → 修复"禁用中会话被复活"。
  - Content-Length header 读循环加 32 行上限，防止异常服务器持续发非空行挂死唯一响应读循环。
  - stderr 落日志前用 `redact_mcp_log_line` 整行脱敏（含 token/api_key/apikey/api-key/secret/password）。

## 进程管理面板（三个需求，均已 tsc + cargo check 4.05s 通过）
1. **表头固定**：根因是滚动容器是 `.side-panel`（`overflow-y:auto`），而 `.process-table` 自己 `overflow:auto` → `process-table-header` 的 sticky 相对不滚动的父元素，等于失效。修复：`.side-panel-header` 加 `position:sticky;top:0;z-index:3;min-height:44px`；`.process-table` 去掉 `overflow:auto`（滚动交回 `.side-panel`）；`.process-table-header` 改 `top:44px;z-index:2`（贴在 header 下方）。**关键：sticky 只相对最近的滚动祖先定位，两者必须匹配。**
2. **升降序切换**：`useSystemMonitor` 新增 `ProcessSortDir` state + `toggleProcessSort(key)`（同列切方向、换列用默认方向：数值列 desc / 名称 asc），图标 ChevronUp/ChevronDown；App 排序比较统一乘 `dir`（desc=-1, asc=1）。
3. **端口列**：`ProcessInfo` 新增 `ports: String`。
   - 远程：`PROCESS_LIST_CMD` 先用 `(ss -H -tunlp || netstat -tunlp)` + awk 建 PID→端口映射，再随 ps 输出第 8 列；`parse_process_list` 读 `parts[7]`。
   - 本地：新增 `collect_local_pid_ports()`（Windows `netstat -ano -p tcp`；其它 ss/netstat），兼容三种 PID 写法（`pid=NNN`、`NNN/prog`、Windows 末列纯数字），去重排序后逗号连接。
   - 降级：采集失败/非 root 看不到 PID 时为空，前端显示 “-”，不影响进程列表。
   - 前端：`api.ts` 类型 + 表头/行“端口”列 + grid 增加一列（`minmax(70px,1fr) 52px 52px 60px 88px`）。
