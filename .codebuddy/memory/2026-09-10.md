## 上下文窗口 / 最大输出 Token 改为「留空 = 默认」（用户要求）
- 输入框不再预填数值：`DEFAULT_AI_CONFIG_DRAFT` 里两者都是 `0`，`normalizeAiContextWindow/normalizeAiMaxTokens` 把 `<=0` 一律保留为 `0`（= 未设置），保存时写 0。
- Rust：原 `DEFAULT_AI_CONTEXT_WINDOW/DEFAULT_AI_MAX_TOKENS` 两个常量合并为 `AI_UNSET_TOKEN_LIMIT = 0`（留空哨兵）；`validate_ai_context_window(0) → Ok(0)`；serde 默认值、`new_default_ai_account`、v1 迁移、`add_ai_provider_account` 全部写 0。
- 留空时的生效默认：上下文窗口 `AI_DEFAULT_CONTEXT_WINDOW = 400_000`（放在 `aiSettingsModel.ts`，供 placeholder 与 `resolveAiContextBudgetChars` 使用；依据 2026 主流旗舰 GPT-5.x 400K / Claude 4.5 200K~1M / Gemini ~1M）；最大输出 token 留空 = 不注入请求体。
- 为什么 max_tokens 不给固定数字：固定值会同时压低新模型（GPT-5.x 128K、Claude 4.5/Gemini 64K）的输出上限，并让 gpt-4o-mini（16384）/deepseek（8192）等端点直接报 `max_tokens` 超限错误；留空即由服务端按模型上限决定。
- 占位符：`默认 400000（token）` / `默认（不限制，交给服务端）`。旧配置若已存了具体数值仍会显示该值，清空即恢复留空。
- 验证：`cargo test` 52 passed、`npx tsc --noEmit`（TSC_EXIT=0）。

## 修复「低风险自动执行」开关无效（用户反馈：开了跟没开一样）
- 现象：Agent 模式下打开开关，动作卡片显示「自动执行」徽标，但动作仍是 `proposed`，还要手点「授权并执行」。
- 根因：`App.tsx` 的 `finishAiStream` 把解析结果写在 `updateAiConversation(...)` 的 **setState updater** 里（`autoRunCapture.job`、`shouldRepairAgentProtocol`），函数返回后立刻读取；React 18/19 只在 fiber 无 pending update 时才同步执行 updater，流式结束时最后一个 delta 的更新常未 flush → 读到 null → 自动执行与协议纠偏都失效（同一个坑，协议纠偏也一直没生效）。
- 修复：把「读取解析产物 → 协议纠偏 / 自动执行 / 冲刷消息队列」整块推迟到 `window.setTimeout(..., 0)`（React 调度走 MessageChannel，先于定时器回调）。
- 顺带修正徽标语义：原来所有低风险 `proposed` 动作都标「自动执行」，实际每条消息只会自动跑**第一个**低风险终端动作（无终端动作时才跑第一条 MCP，跑完由 `continueAgentAfterTerminal` 续跑让模型提出下一步）；现在徽标只用相同的选择逻辑标注真正会被执行的那一条。
- 纯前端改动，Vite 热更新即可，无需重启 tauri。

## 「自动执行」修复迭代（用户反馈：改成 setTimeout 后仍要手动点）
- 第一次修复只是把「读取解析产物」从同步改成 `window.setTimeout(0)`，**仍不可靠**（定时器与 React 调度（MessageChannel）谁先执行没有硬保证），用户复测依旧停在 `proposed`。
- 最终方案（确定性、不再依赖任何调度时机）：
  1. **把解析整体移出 setState updater**：新增 `parseAiAgentTurn(conversation, activeRequest)`，在 `finishAiStream` 里**先**用 `aiWorkspaceRef.current` 的会话快照同步解析，产出 `{ content, proposals, terminalActions, mcpActions, shouldRepairAgentProtocol, autoRun }`，再 `setAiWorkspace` 用结果做纯提交；协议纠偏与自动执行都用同步拿到的结果，彻底摆脱 eagerState 时序。
  2. **幂等派发** `dispatchAiAutoRun(conversationId, messageId, action)`（`aiAutoRunDispatchedRef` 去重），同步路径与兜底路径共用，保证不会重复执行同一条命令。
  3. **状态提交兜底**：`aiAutoRunEligibleRef`（在 `beginAiGeneration` 里登记本回合助手消息 id）+ `useEffect([aiWorkspace,...])` 在提交后复查一次；关闭开关时清空白名单，避免「先提案后开开关」把旧命令突然跑掉。
  4. 徽标与运行时选择逻辑对齐（只标注真正会被执行的那一条）；`dispatchAiAutoRun` 打 `[ai-auto-run]` 控制台日志便于排查。
- 排查提示：若用户仍反馈无效，优先怀疑**前端没热更新到位**（App.tsx 的 HMR 可能失败/页面未刷新），让其 F5 或重启 `npm run tauri dev` 后再看控制台是否有 `[ai-auto-run]`。
