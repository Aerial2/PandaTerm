## 优化目标

完成当前 `workspace-tabs` / `workspace-tab-group` 半迁移，同时保留现有数据模型：顶层按 workspace 排序，激活 workspace 在原槽位展开当前 leaf 的 terminal/RDP 标签组，组内标签按 leaf 顺序管理。

## 实施方案

1. **统一顶栏标签 DOM 与视觉样式**
   - `renderPaneTab` 改为复用 `.workspace-tab`、`.workspace-tab-close` 和相同图标尺寸，只增加必要的 pane/group modifier，不再维护一整套 `.terminal-pane-tab*` 视觉规则。
   - 为 `.workspace-tab-group` 添加明确的单行 flex、固定高度、不可压缩和命中边界；让它作为一个完整 workspace 槽位参与顶层 drop target 计算。
   - 给顶栏补齐 `tablist` / `aria-selected` 语义，并让双击空白判断识别 group，避免双击 pane 标签组间隙意外新建编辑器。
   - 激活 layout 或 `activePaneId` 异常时回退显示普通 root tab，不渲染只有 `+` 的空 group。

2. **修复两层拖拽语义**
   - pane 标签在 `.workspace-tab-group` 内拖动时，以 group 矩形作为本地作用域，复用 `reorderPaneTabIds` 完成当前 leaf 内排序。
   - 本地命中只接受该 group/leaf 的标签，避免 `paneTabElRefs` 命中其他 workspace。
   - 离开 group 后才切换到现有全局拖拽预览；进入 workspace body 后继续支持 pane split/合并。
   - child pane tab 不再触发 root `reorderRootTab`，避免把 child id 交给 root 排序后静默失败；普通折叠 workspace 继续使用原有顶层排序。
   - 将展开 group 注册为顶层 workspace drop target，因此其他折叠 workspace 可正确拖到它前后；不引入额外拖拽手柄，也不改变当前“激活 workspace 展开、失活后可整体拖动”的交互。

3. **清理旧 pane 标签栏残留**
   - 删除已无 JSX 调用的 `.terminal-pane-tabbar`、`.terminal-pane-tabs`、旧 pane tab/close/add 重复样式及失效的 `closest('.terminal-pane-tabbar')` 判断。
   - 去掉旧 pane tabbar 占用的 xterm、连接状态、overlay 和 pane editor 顶部补偿；xterm 回到现有 `8px 12px` 留白，editor/RDP 满铺 pane。
   - 保留分屏 active/drop preview 等仍在使用的规则。

4. **补齐 RDP/SSH 混合 workspace 行为**
   - split divider owner 查找同时接受 terminal 与 RDP root。
   - 可见 layout id 的收集同时接受 terminal/RDP owner，真正创建 xterm 时继续按 terminal kind 过滤，避免 RDP root 下 SSH pane 不挂载。
   - 检查“添加连接到当前 pane”的 root kind 限制并与现有 terminal/RDP 混合布局能力保持一致。

5. **增加纯布局回归测试**
   - 新增 `terminalLayout.test.ts`，覆盖 `findLeafTabGroup`、同 leaf reorder、terminal/RDP owner 查找、激活/移除/插入后的唯一性和 active tab 不变量。
   - DOM 拖拽不引入新的测试框架；通过类型检查、现有 Vitest、生产构建和浏览器实际布局/交互检查验证。
