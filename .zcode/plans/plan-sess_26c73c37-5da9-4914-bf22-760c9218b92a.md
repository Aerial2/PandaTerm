## 实施范围
分阶段完善 PandaTerm，第一阶段先交付日常运维最常用、风险可控的能力：连接稳定性、连接分组/标签、批量连接与断开，并为这些行为增加纯逻辑测试。暂不在本轮同时改动 SSH Agent/GSSAPI、MCP SSE、断点续传或 RDP 协议实现，这些属于独立的高风险阶段。

## 阶段一：连接稳定性
1. 在前端生命周期纯逻辑模块附近新增可测试的重连策略模型/辅助函数，复用现有 `ReconnectPolicy`、`reconnecting` 状态和 `reconnectAttempts` 字段。
2. 明确定义重连条件：仅网络导致的 `failed/disconnected` 触发；用户主动关闭、手动断开或旧 terminal ID 的迟到事件不触发。
3. 实现有上限、可取消、按策略延迟的重连调度，并在重连期间向 tab 展示尝试次数和状态；保留现有 terminal ID 退休与后端 cleanup ownership 机制，避免旧连接事件污染新连接。
4. 在连接成功时更新对应 `Session.last_connected_at`；失败达到上限后保留明确错误原因，不无限重试。
5. 对 SSH 先接入完整重连闭环；RDP 沿用现有 `reconnectNonce`/组件状态，补充统一的手动重试入口，避免把两个不同运行时句柄强行合并。
6. 为退避、最大次数、取消竞态、旧事件过滤、成功复位等场景补充 `terminalLifecycle.test.ts` 及必要的 Rust 纯 helper 测试。

## 阶段二：分组与标签
1. 扩展 `panda-session` 的 `SessionCatalog`，增加分组/标签相关的规范化和批量更新语义；保持现有 Vec<Session> JSON 格式向后兼容，不引入必须迁移的独立索引文件。
2. 对 group 和 tags 做输入清理：去除首尾空白、忽略空标签、标签去重；保留用户可读的原有顺序。
3. 增加按分组/标签筛选与组合搜索的纯函数测试，明确删除/重命名分组时会话迁移策略；首期采用默认分组回退，不删除会话。
4. 在 `ConnectionWindow.tsx` 增加分组筛选、标签筛选/展示和编辑入口，保留现有拖拽排序与多窗口 `sessions-changed` 同步机制。
5. 抽取独立的前端 session model/helper，负责过滤、分组、选中集合和批量结果计算，组件只负责表单和呈现。

## 阶段三：批量操作
1. 增加多选会话 UI，以及全选/清空选择、批量连接、批量断开、批量删除和批量修改分组/标签入口。
2. 在 `api.ts` 与 Tauri 命令层增加批量请求/结果模型；每个会话独立返回成功、失败、跳过和取消原因，禁止批量请求携带明文凭据，只传 session ID 和必要选项。
3. 批量连接使用有界并发和取消机制，避免无界 `Promise.all`；复用现有 `connectSession`、terminal tab 创建和事件路由。
4. 批量断开只操作当前运行中的 terminal，重复执行应幂等；批量删除前阻止删除正在使用的配置，或先安全断开并给出明确结果。
5. 增加批量操作的前端纯函数测试、Rust 参数校验/结果序列化测试，并验证多窗口刷新和排序不回退。

## 验证与交付
- 在每个阶段完成后运行前端 Vitest、TypeScript 构建、`cargo fmt --check`、`cargo check` 和相关 Rust 测试。
- 检查现有未提交修改，不覆盖或回退用户已经改动的 Rust 文件；未跟踪的 `$null` 也只在确认来源后处理。
- 最终补充 README 中与实际行为不一致的连接稳定性、分组标签和批量操作说明，并报告尚未实现的 SSH Agent/GSSAPI、MCP SSE、断点续传和 RDP 产品化工作。
